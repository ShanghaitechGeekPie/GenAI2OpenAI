## 2026-10-28：工具流等待和空回复

实际日志出现过带 32 个工具的请求等待 28～44 秒才返回结果，以及一次空正文。原实现直到完整聚合上游输出后才创建 SSE 响应，等待期间客户端收不到响应头或数据。

现在工具流会立即建立连接，等待期间每 5 秒发送 `: keep-alive` 心跳，完成聚合后再解析工具 JSON。空正文和上游错误会返回 `upstream_error` 事件及 `[DONE]`，不再作为空的成功结果。上游 SSE 读取也取消了默认的 512 字节缓冲，并在结束时关闭连接。

本地 5078 服务验证：

- 13 项自动化测试通过，覆盖延迟心跳、异常传递、断开清理、空回复和工具 JSON 分片。
- DeepSeek 普通对话返回 `OK`；DeepSeek、ChatGLM 均返回 `echo` 工具调用。
- 合成的 74 条消息、32 个工具请求约 3 毫秒收到响应头，约 3 秒返回 `read_file(README.md)`。
- 另一次长请求遇到上游连接超时，等待期间收到 4 次心跳，随后收到明确错误；同一时段上游直连和模型列表查询恢复正常，说明仍存在间歇性连接失败。

以上不包含 GPT 模型，也不代表原 DSH 会话已完成端到端验收。心跳不会显示成正文，工具输出仍须等待上游生成完成。客户端断开后停止继续消费上游；已阻塞的网络读取仍需等待其读取超时结束。

## 2026-10-28：工具数组解析和结束状态

VS Code 截图中的工具调用以顶层数组返回，并在末尾带链接，旧解析器未识别，导致调用 JSON 被作为普通正文展示。现在支持顶层数组、单个嵌套 `function` 对象及尾随文字，多个 XML 工具块也会完整保留。assistant 同时包含正文和调用时，发送给上游的历史不再丢弃调用。

工具名称会与本次请求的工具列表核对，参数必须是合法 JSON 对象；这不代表完整 JSON Schema 校验。损坏或不完整的调用、未知工具以及未满足 required/指定函数约束的输出会明确报错。

普通 Chat Completions 保留上游的 `length` 等结束原因；Responses 文本输出以 `incomplete` 表示未正常完成。未收到结束标记的 EOF 会报错，带工具的响应若被长度限制中断，不会执行从残片解析出的调用。本次未增加 Responses 原生工具支持。

验证结果：25 项本地测试通过；截图格式经过流式及非流式路由回归。5078 服务的 ChatGLM 流式、DeepSeek 非流式均完成两轮真实上游工具往返，工具结果使用夹具，没有执行文件编辑或 Git 操作。未测试 GPT 模型；原 VS Code 会话仍需实际复测。

## 2026-10-28 19:09–19:11：工具 JSON 外层未闭合

用户在 5078 的 DSH 会话中两次遇到 `Invalid or incomplete tool call JSON`。服务日志与会话失败事件对应；用第一次失败前的 31 条上游消息、32 个工具只读重放，复现相同解析错误。上游以 `stop` 结束，生成的 `ask_user_question` 调用及所有嵌套参数均已闭合，但最外层缺少 `]}`。原失败响应未落盘，因此不能声称重放输出与当时逐字相同。重放没有执行任何返回的工具调用。

现在只允许为完整调用补齐缺少的外层调用数组、`tool_calls` 包装对象闭合；参数、字符串、单个调用对象或逗号后的值缺失时仍报错。路由继续拒绝上游 `length` 或异常 EOF 的工具响应，不用此修复掩盖真实截断。解析器也不再因普通正文出现 `"name":` 等字段字样而误报工具协议损坏，普通 JSON 数据和空工具列表在 auto 模式下可作为正文返回。

此前复现失败的输出通过修复后的解析器返回 1 个 `ask_user_question` 调用。28 项本地测试通过，覆盖外层补齐、不可补齐的参数/调用残片、正常正文和流式/非流式路由。失败日志新增正文字符数和结束原因，不记录响应正文。用户原 DSH 会话仍待客户端复测。

## 2026-10-28：空生成恢复和上游字段识别

对应 DSH 19:15:14 的空回复：两次命令工具返回后，下一轮模型聚合结果没有正文。旧日志没有原始字段统计，因此没有证据判定当时上游完全为空还是漏读了其他字段。同一失败前上下文（60 条上游消息、32 个工具）的后续只读重放成功返回正文和调用，故不能声称已修复上游偶发生成行为本身。

本轮修复反代的识别和恢复机制：

- 识别 `reasoning_content` 别名、`choice.message` 完整结果及原生 `tool_calls` / `function_call`；原生工具参数按 index 聚合，并经过相同的名称、JSON 对象参数与 tool_choice 校验。
- 仅在收到正常结束、尚未发布正文或调用时，允许最多一次上游生成重试。仅有思考时先缓冲，失败尝试的思考不会与第二次结果拼接；两次仍无最终输出则明确报错。
- 重试沿用已有工具结果，不调用工具、不增加“继续执行”指令。已有正文或原生调用、业务/网络错误、异常 EOF、length 等结束原因均不重试。
- 每次上游尝试记录共享 request_id、attempt、耗时、事件数、正文/思考字符数、原生调用碎片数、delta/message 字段计数及结束状态；不记录正文、工具参数或凭据。

40 项自动化测试通过，覆盖一次恢复、两次空回复、重试边界、取消生成器、原生工具分片及完整 message 的路由转换、未知工具拒绝和诊断日志脱敏。真实上游与原客户端的验证范围应分别记录，不能以模拟空回复恢复测试宣称用户原任务已完成。

真实上游补充：同一 60 条消息、32 个工具上下文在新代码下约 2.09 秒返回 886 字符正文和 1 个调用；本次没有触发空回复重试。更新后的 5078 上，DeepSeek 非流式两轮往返通过；ChatGLM 流式首次返回正文但未遵守指定 echo 工具约束，被校验拒绝，独立复测两轮通过。有正文的约束失败没有触发自动重试。命令或文件操作均未执行，工具结果仍为夹具；未测试 GPT。新日志能够区分这些有正文的约束失败与真正的空生成。
