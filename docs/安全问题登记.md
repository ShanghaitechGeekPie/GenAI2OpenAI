# Security issue register

Recorded on 2026-10-27. These findings remain open; the core-module split preserves the existing deployment and security behavior.

| ID | Finding | Current behavior | Follow-up |
| --- | --- | --- | --- |
| SEC-001 | Service binds to `0.0.0.0` | Reachable from the local network | Make the bind address configurable and default to loopback |
| SEC-002 | Proxy has no independent authentication | Request tokens pass directly upstream | Add a proxy API key or access control |
| SEC-003 | Unrestricted CORS | Uses `CORS(app)` | Configure an origin allowlist |
| SEC-004 | Plaintext token cache | `.genai_token_cache` stores the token directly | Use a private user directory with restricted permissions; assess encryption |
| SEC-005 | Requesters can supply arbitrary image URLs | Server downloads supplied URLs | Restrict schemes, hosts, size and redirects to address SSRF |
| SEC-006 | Unbounded image-upload cache | In-memory dictionary has no expiry or capacity limit | Add capacity limits, expiry and token isolation |
| SEC-007 | Hardcoded upload token | CLI default contains a fixed token | Read it from external configuration or an environment variable |
| SEC-008 | Suspected real credential examples | Auto-login README contains concrete account/password-shaped strings | Replace with placeholders and inspect commit history |

The findings cover deployment, authentication, token storage, image proxying and credential examples. Remediation is pending.
